# AI 일정 식사 슬롯 정책

상태: 현재 동작 설명
마지막 검증: 2026-09-26

식사 슬롯의 최종 source of truth는 다음 Java 정책 API다.

- `MealSlotPolicy.missingMeals(...)`: Java가 채우기를 시도할 등록 식사
- `MealSlotPolicy.requiredMissingMeals(...)`: 끝까지 없으면 일정을 거부할 식사
- `MealSlotPolicy.configuredMealTime(...)`: 슬롯을 생성할 등록 식사시각

Prompt는 식사 후보와 음식점을 선택할 수 있지만 식사 개수, 면제와 최종 통과 여부를 결정하지
않는다. `MissingSlotCompleter`가 슬롯을 보정하고 `PlanService`가 최종 결과를 검증한다.

## 등록 식사 판정

판정 대상은 `BREAKFAST`, `LUNCH`, `DINNER`다.

- 선택된 동행인이 없으면 식사 규칙을 적용하지 않는다.
- `mealInfo.applied()`가 `false`이면 해당 동행인의 식사정보를 사용하지 않는다.
- 끼니별 적용 플래그가 `false`이거나 시간이 없으면 해당 끼니를 등록 식사로 보지 않는다.
- 여러 동행인이 같은 끼니에 서로 다른 시간을 등록하면 가장 이른 시간을 사용한다.
- 하루의 첫 슬롯과 마지막 슬롯 시각은 식사 요구 여부를 결정하지 않는다.

## 채우기 대상과 거부 대상

`missingMeals(...)`는 시작 시각이 있는 슬롯이 하나 이상인 날에서 일정에 없는 등록 식사를
모두 반환한다. 일정이 비었거나 모든 슬롯의 시작 시각이 없으면 보정 기준을 만들 수 없어 빈
목록을 반환한다. 여행 첫날이나 마지막 날도 채우기 단계에서는 가능한 모든 등록 식사를
생성하려고 시도한다.

`requiredMissingMeals(...)`는 다음 두 식사만 최종 거부 대상에서 제외한다.

- 1일차 `BREAKFAST`
- 마지막 일차 `DINNER`

첫날은 이동 후 늦게 시작하고 마지막 날은 귀가로 일찍 끝날 수 있기 때문이다. 면제는 최종
거부에만 적용된다. 사용할 수 있는 후보가 있으면 `MissingSlotCompleter`는 면제 식사도 채우기를
시도한다.

## 보정 순서

`MissingSlotCompleter.complete(...)`는 필수 식사와 선택 식사를 나눈 두 번의 보정 단계에서 각각
관광 슬롯을 먼저 채우고 식사 슬롯을 채운다. 식사 보정과 뒤이은 확정 순서는 다음과 같다.

1. 필수 식사를 먼저 채운다.
2. 첫날 아침과 마지막 날 저녁 같은 선택 식사를 채운다.
3. 같은 장소명과 같은 대표메뉴를 여행 전체에서 다시 사용하지 않는다.
4. 슬롯 추가로 직전 장소가 바뀐 기존 슬롯의 `travelMinutes`를 무효화한다.
5. `PlanService`가 확정 좌표로 누락된 이동시간을 다시 조회하고 시간을 정규화한다.

식사 후보는 TourAPI 음식점 상세정보에서 비어 있지 않은 대표메뉴를 확인할 수 있어야 한다.
장소명이나 대표메뉴가 이미 사용됐거나 상세 조회에 실패한 후보는 건너뛴다.

## 생성과 편집 검증

생성 경로는 `requiredMissingMeals(...)`가 반환한 식사가 남으면 최종 일정을 거부한다.

편집 경로는 편집 전 일정에 이미 없었던 식사를 새 누락으로 취급하지 않는다. 기존 일정에
없던 식사를 편집 요청과 무관하게 강제하면 사용자가 식사와 관계없는 편집까지 완료할 수 없기
때문이다. 편집으로 새로 생긴 날짜는 비교할 기존 날짜가 없으므로 이 면제를 적용하지 않는다.

보정은 무한 반복하지 않는다. 최종 finish 경계에서 한 번 더 누락 식사를 채우고, 이후에도
필수 식사가 없으면 명시적으로 실패한다.

## Prompt와 Java의 책임

`TravelPlanPrompt`, `EditPlanPrompt`, `RebuildPlanDayPrompt`는 다음 경계만 안내한다.

- 실제 음식점과 메뉴는 Tool 결과에서 선택한다.
- AI가 `MEDICATION` 슬롯을 생성하지 않는다.
- 식사·복약의 최종 시간 계산과 검증은 Java가 수행한다.

첫날 아침과 마지막 날 저녁 면제, 동행인별 적용 플래그와 최종 거부 여부는 Prompt에 복제하지
않는다.

## 회귀 테스트

현재 계약은 다음 테스트에서 검증한다.

- `MealSlotPolicyTest`
  - 등록 식사 전체가 채우기 대상인지 확인
  - 첫날 아침과 마지막 날 저녁의 거부 면제 확인
  - 중간 날짜의 등록 식사 전체 요구 확인
  - 식사정보 미적용 처리 확인
- `MissingSlotCompleterTest`
  - 실제 대표메뉴를 사용한 슬롯 생성 확인
  - 장소명·대표메뉴 중복 후보 제외 확인
  - 후보 부족 처리 확인
- `PlanPlaceValidationTest`
  - 생성·편집 최종 식사 검증과 기존 편집 일정 면제 확인
- `PlanDayRebuildContractTest`
  - Prompt가 식사 면제 계산을 소유하지 않고 복약 생성을 Java에 위임하는지 확인
