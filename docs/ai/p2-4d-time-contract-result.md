### 12-4. 미확정과 증거 부족

- 400 응답 본문(Kakao 오류 코드) 미기록. Kakao 공통 오류 -10(호출 한도 초과)은 HTTP 400을 사용([REST API 레퍼런스](https://developers.kakao.com/docs/ko/rest-api/reference))하므로 **호출 한도(일일·초당)가 후보이나 요청 형식 오류·권한 변경과 구분 불가**. `/v2/routing/publictraffic`의 공개 문서·한도도 이번 조사에서 미확인
- 생성·REST 편집 실행의 애플리케이션 로그는 이후 Gradle 실행이 JUnit XML을 덮어써 소실. 생성 사례별 공급자 상태는 이동수단 분할·실패 메시지·시간 패턴으로 추정
- Kakao 경로 조회 meter 부재(`planb.external.kor2.response`와 대비). 실행별 대중교통 호출 수·실패 수 미집계
- 초당·동시 호출 제한(`lookup-concurrency:4`) 가능성: STOMP의 단일 순차 조회도 400이라 순간 폭주 제한 가능성은 약하나 배제 못 함. 20:30:50 자체는 한 요청 안의 2ms 간격 2구간만 실패한 부분 실패라 한도 경계와 순간 제한 모두에 부합
- 20:30:50 이후 TRANSIT 200이 한 번이라도 있었다면(C3 2·3회차 재계산의 가능성) 20:30 일일 한도 소진만으로 설명 불가. 따라서 -10 일일 한도는 유력 후보 중 하나이며 간헐·초당 제한과 동등하게 미판별
- 같은 앱 키의 장소 검색은 STOMP 시점에도 성공(로그된 예외 유형으로부터의 추론) → 키 무효화보다 API별 한도 또는 endpoint 고유 원인 쪽 근거
- 이전 실측(§9·§11)의 성공률 차이 17/18 → 6/18: STOMP는 400 → 경로 결과 누락 → 거부를 직접 관측, 생성12건·REST2건의 공급자 상태는 로그 소실로 추정. 전체 실행의 인과관계 확정 금지, 복약 계약 품질 비교 지표로 사용 불가
