## 3. 변경

### #181 등록 간격 유지 (PR #185)

- `ScheduleNormalizer.moveOutOfPlaceSlots`·`nonMealPlaceSlots` 제거
- 식전 = 식사 시작 − 간격, 식후 = 식사 종료 + 간격, 식중 = 식사 시작, INDEPENDENT·REGARDLESS_OF_MEAL = 등록 시각. 10분 슬롯 유지
- 같은 시각 병합 유지. 동행인 규칙별 준수는 원본 healthContexts 기준 테스트로 판정

### #182 겹침 회피 (PR #187)

- `ScheduleNormalizer.finalizeMedicationSchedules`: 날짜별 복약 생성 → 첫 교차 탐색 → 해당 장소만 복약 종료 시각 시작으로 이동 → `normalizeScheduleTimes` 재실행(뒤 장소는 기존 이동시간 제약으로 연쇄) → 기존 충족 식사·자정 검증 → 재검사
- `PlanService.finishPlan`의 최종 복약 배치만 교체. 중간 `validatePlaces`는 기존 `ensureMedicationSchedules` 유지
- 직전 장소와 겹친 식전 복약: 장소 이동은 식사·복약을 함께 밀어 해소 불가하므로 식사만 창 안에서 지연(`delayMealForBeforeMedication`)
- 재정규화의 늦은 식사 보정이 장소를 앞당기면 `장소 앞당김 필요`로 거부, 앞당김 금지 유지. 해당 식사가 원래 창 밖이었어도 동일 거부(규칙보다 엄격)
- `validateMealSlots`(필수 식사 존재)는 finalize 이전 실행. finalize는 슬롯을 추가·삭제하지 않아 재검증 불필요
- 자정 순환 판정: 종료 역전은 이번 이동으로 시각이 바뀐 장소만, 이동시간 제약 위반은 이동 장소와 그 직후 장소 대상. 자정에 끝나는 장소는 당일 끝까지 구간으로 겹침 판정
- 등록 식사시각이 없는 식사는 창 제약이 없어 식전 복약 지연 허용
- 거부 사유 4종: `복약 겹침 회피 시 식사시간 이탈`, `복약 겹침 회피 시 장소 앞당김 필요`, `복약 겹침 회피 시 자정 초과`, `복약·장소 시간 겹침`
- 예외는 반환·저장 이전 `finishPlan` 내부 발생, 부분 저장 없음(생성 저장은 Facade 반환 이후, 편집 결과 캐시도 반환 이후)

## 6. 한계

- 실제 AI 응답 기준 효과 미측정. 겹침 회피 거부가 생성 실패율을 올릴 가능성 존재. 기존 실측 fixture(C1~C4)는 식후 규칙만 사용해 식전 경로 미관측
- 겹침 상한 3회는 겹침 건수 기준. 세 끼 식후 복약 + 고정 복약이 모두 장소와 겹치는 날은 4건으로 거부
- 같은 시각으로 병합된 식전 복약과 고정 복약은 식사 지연 후 잔존 겹침에 장소 이동 1회 추가 소모
- 같은 유형 식사 슬롯이 하루 두 개면 복약 기준은 첫 슬롯, 두 번째 슬롯 앞 장소의 식사 지연 매칭은 미보장
- 식사 지연은 겹친 장소 바로 다음이 기준 식사일 때만 적용. 장소와 식사 사이에 다른 장소(카페 등)가 있으면 장소 이동이 식사·복약을 함께 밀어 상한 또는 식사시간 이탈로 거부
- 이동된 장소가 정확히 00:00에 끝나면 자정 초과로 거부, 원래 00:00 종료 장소는 당일 끝까지 구간으로 허용(비대칭)
- 식전 판정은 `식사 시작 − 등록 간격 = 복약 시작` 시각 일치 기준. 고정·다른 식사 복약이 우연히 같은 시각이면 식사 지연 후 장소 이동으로 넘어가 1회 추가 소모
- **정책 위험(통합 리뷰 Important, 사용자 정책 범위):** 세 끼 모두 식전·식후 복약이 있고 여유 없는 일정(예: 아침 8~9시, 이동 15분)은 식후 이동이 점심을 밀고 식전 간격 확보가 창을 넘어 거부 가능. 상한 3회 초과도 가능. 코드 결함이 아닌 "뒤로만·3회·거부" 정책 결과로, 실측 시 이 프로필 별도 분모로 생성 실패율 확인 필요
- `intervalMinutes` 입력 검증 없음(null·음수 허용), 새 정책이라 미변경
- 자정 근처 `LocalTime` 순환: 복약 종료 순환 시 겹침 미검출 가능, 이동 결과 순환은 거부
- 하루 이동 상한 3회는 고정값, 실측 분포 근거 없음
- 편집 `preserveOtherDays`: 재구성 날짜와 직후 날짜만 `finishPlan` 경유, 나머지 보존 날짜의 기존 겹침은 미검사
- 서브 PR의 base가 부모 브랜치라 GitHub CI는 부모 PR에서만 실행
- 장소 identity 한계는 §3 #183
