# P2 선택 계약 정렬 결과 — Issue #177

작성일: 2026-10-11. 기준 코드: dev `127e1a2a70e074909d965f3600f5dc17d6b29caa`(채택 P2-4A). 미채택 P2-4B·P2-4C 누적 제외.

## 결과와 증명 범위

생성·슬롯 재선택·Java 식사 보충의 음식점 메뉴 출처 계약을 같은 요청 컨텍스트로 정렬. 후보의 장소 identity 검증과 별개로 TourAPI 상세의 contentid·contenttypeid·성공 코드 및 실제 메뉴 목록을 검사.

무료 테스트는 조회 원본과 선택 값의 관계를 검증하는 증거. 실제 AI 품질 개선·생성 성공률 개선은 아직 미측정. 기존 API 12회 승인의 후속 사용 없이 별도 승인 대기. 전체 품질 문제 해결 또는 운영 채택 완료로 기록하지 않음. 전달 대상은 dev이며 main 동기화 제외.

## 경계 조건

- 성공 코드 0000·00만 상세 메뉴 근거로 사용. 누락·실패 헤더, 빈 상세, 다른 음식점·유형의 상세는 거부
- 쉼표·슬래시·세미콜론·파이프·줄바꿈·HTML br의 목록 구분과 앞뒤 공백 제거만 허용. 부분 문자열·별칭·유사도 승인 제외
- 같은 요청에서 정상 반환한 보충 조회는 원본 미확인 결과라도 반복 조회 방지. 이 표시는 메뉴 출처 증거가 아님
- 조회 예외는 완료로 기록하지 않아 후속 보충 재시도 유지. clear 시 후보·메뉴·조회 완료 표시 함께 제거
- 잘못된 상세 응답으로 이미 확인된 정상 원본 덮어쓰기 방지. 요청 간 메뉴 상태 격리
- TourAPI 음식점(tour:·39)만 신규 출처 검사. Kakao FD6는 기존 호환성 유지이며 신규 출처 증명의 대상 아님

## 검증

TDD RED/GREEN: 다른 식당 상세로 식사 보충되는 문제, 잘못된 메뉴의 최종 승인, 최초 생성 callback의 조회 근거 누락, 정상 반환한 잘못된 상세의 반복 조회를 각각 실패 테스트로 확인 후 수정.

Review-loop: 구현 검토 3회 모두 9/10, 최종 Critical·Important 0건. 최초 생성 FD6 호환성 테스트, 파이프 구분자 명시, clear 후 재조회 테스트의 경미한 지적도 반영.

Java 21의 `./gradlew clean test`: 135개 suite, 885건 통과, 실패·오류·skip 0건, 3분 43초. 검증 코드 commit `3b766cf16e4e4d8ae226a247b50bc71e073057db`. 결과는 `p2-selection-contract-verification.json`에 기록. 외부 API 호출 테스트는 실행 전 승인 대기.

테스트 fixture의 상세 contentid가 검색 음식점과 다르던 부분을 요청 ID와 일치하도록 정정. 실제 선택 메뉴로 임의 근거를 만들지 않고 고정 원본 메뉴를 사용. 기존 편집·복구 결과의 단언 유지.

## 한계와 다음 순서

메뉴 목록의 원문 일치는 실제 재료·알레르기 안전성과 현재 영업을 증명하지 않음. 원문이 모호하면 거부가 늘 수 있으므로 실제 생성 12회의 품질 gate 필요. 동시 요청은 컨텍스트별로 격리되며 동일 컨텍스트 안의 병렬 상세 조회 coalescing은 이번 범위 밖.

후속 2단계는 실패 종류별 복구와 정상 슬롯 보존을 확인하는 작업. 기존 PlanService 슬롯 재선택을 먼저 조사하고 재시도 예산 증가 없이 실제 결함을 구분. 3단계 필수 일정 골격과 4단계 판단 의존 분리는 앞선 실패 증거를 확인한 뒤 도입 여부 결정.
