## 1. 결론과 증명 범위

이번 Part 2의 핵심은 모델 응답이 성공 형식을 갖추는지보다 **후보 원본·메뉴·사용자 선택·시간 규칙·편집 범위가 실제 결과에 유지되는지**를 분리해 확인한 점.

- 지정 장소를 무작위 후보에 맡기는 대신 Java가 검색·고정하고, 생성 응답의 장소 사실값을 `candidateId` 원본으로 복원하는 계약 확립
- 괄호를 포함한 메뉴 원문 처리와 구조화 correction 안내 보강, 공원 검색 자격과 최종 guard 정렬, 정상 슬롯 선예약과 실패 슬롯별 최대 두 번 재선택
- 등록 복약 간격을 Java에서 유지하고 이동·관광·카페 체류와 복약 알림의 중첩 허용. 복약 때문에 장소·식사를 미루던 정책은 최종 승인 정책으로 대체
- 새로 선택하는 식사에 등록 알레르기 이름·승인 분류어 guard 적용. 원재료 미상과 문자열 검사 통과를 구분
- 부분 편집의 대상 밖 선택을 원본으로 복원하고, 선조회 후보 삭제 결함(P0)을 최소 수정. 실측에서는 같은 음식점 메뉴 변경·대상 밖 선택·preview/cancel 원본 보호를 함께 확인
- 캐시·공급자 오류·STOMP 전달·첫 검증·재선택의 관측을 추가해 모델 품질, Java 계약, 외부 공급자, 전달 문제를 분리

실제 결과는 서로 다른 날짜·모델 응답·외부 API·캐시 상태의 소표본. 성공 건수나 지연 변화만으로 코드의 인과 효과·통계적 유의성·운영 처리 용량을 확정하지 않는 기준.

## 2. 배경과 기준선

Part 1은 DB 커넥션 점유·요청 간 동시성·영양 조회 대기 중첩의 자원 문제를 다룬 실험. Part 2는 실제 AI 호출을 사용해 후보·메뉴 선택과 요청 반영의 품질을 조사한 별도 범위.

초기 기록의 “12/12 거부”는 P2-0 재측정에서 11/12 통과로 바뀐 관측. 당시 실패 원인은 미확정이며 후속 TourAPI 오류와 동일 원인으로 단정하지 않는 기준. PASS는 구조 invariant 통과이지 여행 품질 전체의 정답 판정이 아니므로, 지정 장소 포함 3/11과 부분 편집의 요청 밖 변경을 별도 문제로 정의.

P2-1에서 LLM 시간 비중30.9%, 영양 평가 Tool50.2% 관측으로 “생성 지연의 대부분이 LLM” 가설 H1 기각. 영양·TourAPI 조회 최적화 후 R1에서 LLM 비중60% 관측을 구조 재검토 근거로 사용. 이후 사용자 결정으로 품질·안정성을 주 채택 기준으로 전환하고 지연·token·호출 수는 보조 지표로 유지.

| 기준 | 역할 |
|---|---|
| R0: P2-2 제목 일치 보강 뒤 재측정 | 누적 품질·감시 지표의 기준. 초기 R0 1차와 구분 |
| R1: P2-3D 통합 측정 | 누적 지연·비용 보고 출발점. 자동 채택 gate 아님 |

| 결정적 fixture | 주어진 원본·실패 입력에서 계약·재선택 범위·보존의 증거 |
