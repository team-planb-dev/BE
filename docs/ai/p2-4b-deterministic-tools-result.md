# P2-4B 결정적 Tool의 Java 이전 검증 결과

작성일: 2026-10-10. Issue [#172](https://github.com/team-planb-dev/BE/issues/172). 기준 코드 `2a99375`, 변경 후 브랜치 `172-perf-move-deterministic-travel-generation-tools-to-java`의 미커밋 변경. 상태: 구현 독립 검토 8/10. 실제 API 생성 12회 완료, 주 품질·지연 gate 미달로 미채택. dev/main 병합 보류.

## 변경 범위

생성 경로에서 검색 Tool 3개만 등록하고 음식점 상세·메뉴·영업시간 준비, 최종 영양 평가를 Java로 이동. 편집과 날짜 재구성의 기존 Tool 유지. 기존 재선택 Tool은 유지하되 생성 결과 수락 시 요청의 메뉴 출처·알레르기·영업시간을 재검증하고 최종 확정 메뉴로 Java 영양 평가 수행. 공개 DTO, DB 스키마, Facade, 트랜잭션 경계 변경 없음.

표준명은 candidateId·메뉴 쌍으로 연결하고 폐기된 슬롯의 값 덮어쓰기 방지. 후보 조회량에 요청 상한·중복 방지 적용. 영업시간은 해석 가능한 단일 구간만 사전 필터에 사용하고 불명·fallback·실제 시각 불일치 별도 관측.

### 실패와 호출 증폭 — 확인 사실과 가설

- 부산 3회 모두 `PLAN.EXCEPTION.INVALID_AI_PLACE`, `restaurantDetail: 재선택 메뉴 원본 불일치`로 저장 거부. 첫 2회는 2일차 08:00, 마지막은 2일차 18:00 슬롯. 외부 API 인증 실패로 분류하지 않음.
- `PlanService.recoverPlace`가 레거시 재선택 결과를 생성 요청의 `GenerationRestaurantCandidates.accepts`로 재검증. `accepts`는 준비된 후보, 정확한 메뉴 문자열, 식사 유형 자격을 함께 검사. 현재 실패 메시지만으로 어느 조건인지 확정 불가. 상세 준비 상한·배제 후 후보 부족·메뉴 표현 차이·영업시간 유형 필터는 구분 조사 필요.
- 재선택은 계획대로 기존 `PlanTourismTool`과 `PlaceReselectPrompt` 유지. 실제 기록에 `getRestaurantDetail` Tool 13회, `evaluateFoodNutrition` Tool 10회 포함. 생성 최초 Tool만 줄여도 재선택의 결정적 Tool과 모델 왕복은 사라지지 않는다는 실행 증거.
- 서울 첫 실행은 `ai_response` 약 14.150초, `place_validation` 약 32.758초, 그 안의 `reselect` 2회 합계 약 30.077초. `finish_plan` 약 17.320초, 그 안의 `nutrition_enrichment` 약 16.471초. 부모·자식 구간 중첩이므로 이 시간을 모두 합산하지 않음. 최초 생성 뒤의 재선택이 해당 요청 지연에 크게 기여.
- 메뉴 준비는 대표 메뉴 `firstmenu` 우선, 비어 있을 때 `treatmenu`. 레거시 재선택은 실제 메뉴·영양 평가를 요구하지만 같은 준비 메뉴 목록을 프롬프트에 제공하지 않음. 생성과 재선택 사이 메뉴 계약 차이는 코드상 위험이며, 부산 실패의 확정 원인으로 단정하지 않음.
- 알레르기 추정 1건은 서울 첫 실행 2일차 `늘봄해물찜&손칼국수 답십리본점`, 메뉴 `아구찜`의 음식점명 `해물`에 적중. 메뉴 문자열에는 해당 키워드 없음. 기존 지표는 음식점명과 메뉴명을 모두 검사하며 오탐 가능성이 있음. 실제 새우 포함 여부 미확인. 이번 실행에서만 임의로 적중을 삭제하거나 gate를 완화하지 않음.
- 요청 측정 구간에 기록된 TourAPI 응답은 135건이며 모두 `ok`. 생성 종료 뒤의 메뉴 출처 확인 호출은 이 계수 밖이므로 총 공급자 사용량으로 주장하지 않음.

### 검증 범위와 다음 시작점

Gradle `externalTest`는 BUILD SUCCESSFUL, JUnit 12건·실패 0·건너뜀 0. 실행기는 API 실패도 결과로 기록하는 관찰 테스트이므로 **JUnit 성공과 일정 생성 12/12 성공은 다른 판정**. 코드 독립 리뷰 8/10·무료 테스트 888건도 실제 품질 gate를 대체하지 않음.

HIGH 비율은 공개 응답에 등급·분모가 없어 N/A. 영업시간 불일치 증감은 P2-4A 비교 기준 미측정으로 판정 불가. 카페 감시 기준을 넘었지만 주 품질·지연이 이미 미달하므로 기준 통과를 위해 추가 유료 12회 자동 실행하지 않음.

다음은 재선택의 후보·메뉴 계약과 발생 이유를 먼저 구분할 단계. 확정되지 않은 원인을 근거로 검증을 완화하지 않음. 현재 코드는 #172 브랜치의 미커밋 상태로 보존하고 운영 채택·Issue 완료·dev/main 병합을 수행하지 않음. 추가 실제 호출은 이번 12회 승인 범위 밖으로 별도 결정.
