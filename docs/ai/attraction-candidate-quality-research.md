# 관광지 후보 품질 필터 조사

조사 기준일: 2026-09-23  
기준 브랜치: `75-bug-prevent-low-quality-attraction-candidates-from-entering-travel-plans`  
범위: TourAPI KorService2 `contentTypeId=12` 지역 후보의 분류체계와 최소 안전 필터

## 결론

`contentTypeId=12`와 신분류 코드 중 어느 하나도 "여행 일정에 넣기 좋은 관광지"를 보증하지 않는다. 실제 강릉 응답에는 일반 교회, 노인회 지회, 사회복지관, 여객터미널, 해변 화장실, 일반 사우나가 포함됐다.

공식 분류명과 재현 데이터를 함께 보면 이 현상은 단순 코드 오독이 아니다.

- `VE010100`은 `문화관광 > 랜드마크관광 > 건물`이므로 관광 건축물과 화장실 같은 일반 건물이 섞일 수 있다.
- `EX050100`은 `체험관광 > 웰니스관광 > 온천 / 사우나 / 스파`이므로 관광 온천과 일반 사우나가 섞일 수 있다.
- `EX070100`은 `체험관광 > 기타체험 > 유람선/잠수함관광`이지만 실제 결과에는 여객터미널과 대합실도 들어온다.
- `HS030200`은 `역사관광 > 종교성지 > 기독교`이므로 역사적 성당과 일반 교회가 섞일 수 있다.
- `VE120300`은 `문화관광 > 기타문화관광지 > 기타문화시설`이라는 포괄 분류다.
- `VE050100`은 공식 명칭이 `문화관광 > 복합관광시설 > 관광단지`지만, 실제 결과에는 종합 관광휴양지와 산업용품 유통 상가 단지가 함께 들어온다.

`VE120300`은 PlanB가 관광 일정 품질을 우선해 **코드 전체를 제외하기로 한 제품 정책**이다. 공식 명세가 이 코드를 비관광 시설이라고 선언한 것은 아니므로, 이 결정은 공식 사실과 구분해서 유지한다.

그 밖의 혼합 분류를 제목 금칙어로 하나씩 막는 denylist는 새 시설명이 들어올 때마다 같은 문제가 반복된다. "누가 봐도 관광지인 분류만"을 목표로 한다면 최종 계약은 **분류 allowlist에 있는 후보만 통과시키고, 알 수 없거나 혼합된 분류는 기본 제외하는 방식**이 더 결정적이다.

권장 순서는 다음과 같다.

1. 이미 결정된 `VE120300` 전체 제외와 일반 교회 회귀 방지는 그대로 유지한다.
2. 아래의 보수적 allowlist를 공통 후보 선택 seam에 적용한다.
3. 후보가 부족한 지역이 실제로 확인될 때만 혼합 분류를 코드별로 재검토한다. 제목이나 이미지 조건으로 원본 후보를 복원하지 않는다.

## 공식 TourAPI 계약

한국관광공사의 공공데이터포털 명세는 KorService2의 base URL을 `https://apis.data.go.kr/B551011/KorService2`로 제시하고 다음 operation을 별도로 제공한다.

- `/areaBasedList2`: 지역기반 관광정보조회
- `/categoryCode2`: 서비스분류코드조회
- `/lclsSystmCode2`: 분류체계 코드조회

공식 명세에서 `/categoryCode2`는 “미사용 기능, 분류체계 코드로 대체”라고 표시된다. 기존 `categoryCode2`는 `contentTypeId`와 `cat1`·`cat2`·`cat3`를 사용하지만, 새 `/lclsSystmCode2`는 `lclsSystm1`·`lclsSystm2`·`lclsSystm3`와 전체 목록 조회용 `lclsSystmListYn`을 제공한다. ([공공데이터포털 KorService2 공식 명세](https://www.data.go.kr/data/15101578/openapi.do))

한국관광공사 공지는 두 체계를 다음처럼 구분한다.

- 구분류 `categoryCode2`: `contentTypeId`에 따라 대·중·소 분류
- 신분류 `lclsSystmCode2`: 세부 신분류체계에 따른 대·중·소 분류
- 신분류는 `contentTypeId`별 분류가 아니다.
- 구분류는 삭제 예정이므로 신분류를 사용해야 한다.

즉 `contentTypeId=12`와 `lclsSystm*`은 서로 다른 축이다. `12`만 검사해서 관광 일정 적합성을 판정할 수 없다. ([한국관광공사: 법정동코드·신분류코드 안내](https://api.visitkorea.or.kr/#/cmsNoticeDetail?no=207))

### `areaBasedList2` 입력과 응답

공식 Swagger 명세에서 `/areaBasedList2`는 다음 필터를 받는다.

- 관광 유형: `contentTypeId`
- 구 지역: `areaCode`, `sigunguCode` — 법정동 코드로 대체 예정
- 신 지역: `lDongRegnCd`, `lDongSignguCd`
- 구 분류: `cat1`, `cat2`, `cat3` — 신분류로 대체 예정
- 신 분류: `lclsSystm1`, `lclsSystm2`, `lclsSystm3`
- 정렬: `arrange`; `O`, `Q`, `R`은 대표 이미지가 반드시 있는 결과만 제목·수정일·생성일 순으로 정렬

응답 item에는 식별·표시·위치 필드와 신분류가 함께 있다.

```text
contentid, contenttypeid, title
addr1, addr2, zipcode
mapx, mapy, mlevel
firstimage, firstimage2, cpyrhtDivCd
createdtime, modifiedtime, tel
lDongRegnCd, lDongSignguCd
lclsSystm1, lclsSystm2, lclsSystm3
```

따라서 후보 품질 판정을 위해 새 외부 호출을 추가할 필요가 없다. 현재 `areaBasedList2` 응답에 필요한 코드와 이미지 필드가 이미 들어 있다. `lclsSystmCode2`는 코드명을 갱신하거나 관리 화면에 표시할 때 유용하지만 요청마다 호출할 이유는 없다. ([`areaBasedList2` 공식 명세](https://www.data.go.kr/data/15101578/openapi.do#/API%20%EB%AA%A9%EB%A1%9D/areaBasedList2), [`lclsSystmCode2` 공식 명세](https://www.data.go.kr/data/15101578/openapi.do#/API%20%EB%AA%A9%EB%A1%9D/lclsSystmCode2))

### 보수적 allowlist

다음 그룹은 분류명 자체가 역사 유적·자연 경관·체험 활동·명시적인 관광 시설을 가리키므로 기본 허용한다.

| 허용 단위 | 코드 | 공식 의미 |
| --- | --- | --- |
| 중분류 전체 | `HS01`, `HS02`, `HS04` | 역사유적지, 역사유물, 안보관광지 |
| 중분류 전체 | `NA01`, `NA03`, `NA04` | 자연경관(산), 자연생태, 자연공원 |
| 소분류 | `NA020100`~`NA020600`, `NA020800`, `NA020900` | 강·호수·저수지·연못/늪·섬·염전·해안절경·해변/해수욕장 |
| 중분류 전체 | `EX01`, `EX02`, `EX03`, `EX04`, `EX06` | 전통체험, 공예체험, 농·산·어촌체험, 산사체험, 산업관광 |
| 소분류 | `VE010200`~`VE010800` | 타워/전망대부터 등대까지 구체적인 랜드마크 |
| 중분류 전체 | `VE02`, `VE04` | 테마공원, 도시·지역문화관광 |
| 소분류 | `VE030500` | 주제공원 |
| 소분류 | `VE070100`, `VE070200`, `VE070300`, `VE070500`, `VE070600` | 박물관, 기념관, 전시관, 과학관, 미술관/화랑 |

다음은 분류만으로 관광 일정 적합성을 확정할 수 없으므로 기본 제외한다.

| 제외 단위 | 공식 의미 | 실제 또는 구조적 위험 |
| --- | --- | --- |
| `HS03` 전체 | 종교성지 | 일반 종교시설과 역사적 성지가 섞임 |
| `NA020700` | 항구/포구 | 관광 포구와 생활·산업 항구가 섞임 |
| `NA05` 전체 | 기타자연관광 | 단일 catch-all |
| `EX05` 전체 | 웰니스관광 | 일반 사우나·찜질방·뷰티스파와 관광 웰니스가 섞임 |
| `EX07` 전체 | 기타체험 | 여객터미널과 실제 체험 관광이 섞임 |
| `VE010100`, `VE010900` | 건물, 기타 건축/조형물 | 화장실 같은 일반 건물이 들어옴 |
| `VE030100`~`VE030400` | 시민·소·어린이·근린공원 | 생활권 공원인지 관광지인지 분류만으로 구분할 수 없음 |
| `VE050100` | 관광단지 | 종합 관광휴양지와 산업용품 유통 상가 단지가 같은 코드에 섞임 |
| `VE050200` | 리조트 | 숙박·부대시설과 관광 장소가 섞임 |
| `VE06`, `VE08`~`VE12` | 공연·행사·교육·스포츠·교통·기타시설 | 일정·이용 목적이 필요하거나 일반 생활시설을 포함함 |
| 코드 없음 또는 미지 코드 | 의미 확인 불가 | 분류 계약을 적용할 수 없음 |

이 allowlist는 보수적인 시작점이다. 제외 그룹의 실제 관광지를 다시 포함하려면 코드만으로는 부족하므로, 별도의 검증 가능한 근거와 유지·제외 fixture를 함께 추가해야 한다.

`VE050100`이 혼합 분류라는 판단은 공식 분류명을 부정하는 것이 아니다. 한국관광공사 관광데이터의 `경주 보문관광단지`는 같은 `관광단지` 범주에서 호텔·콘도·수상시설·산책로 등을 갖춘 종합 관광휴양지로 설명된다. 반면 `구로기계공구단지`는 같은 범주이지만 기계공구와 산업용품 유통업체 약 1,700곳이 모인 상가 단지로 설명된다. 따라서 `VE050100`은 한국관광공사 콘텐츠 분류로는 모두 유효하지만, 사용자 취향과 무관하게 기본 일정에 넣을 "명확한 관광지"만 허용하는 PlanB 계약에는 충분한 판별 기준이 아니다. ([한국관광공사 관광데이터: 경주 보문관광단지](https://data.visitkorea.or.kr/linkedview/126230), [한국관광공사 관광데이터: 구로기계공구단지](https://data.visitkorea.or.kr/linkedview/2591803))

## 재현 데이터가 보여주는 문제

2026-09-22 외부 통합 로그의 강릉 `areaBasedList2(contentTypeId=12)` 응답에서 다음 항목을 확인했다.

| 제목 | 신분류 | 이미지 | 판정 근거 |
| --- | --- | --- | --- |
| `강릉교회` | `HS / HS03 / HS030200` | 없음 | 일반 교회명이며 관광 가치 근거 없음 |
| `금강사(강릉)` | `HS / HS03 / HS030100` | 있음 | 같은 종교 중분류지만 관광 콘텐츠 근거 있음 |
| `보현사(강릉)` | `HS / HS03 / HS030100` | 있음 | 같은 종교 중분류지만 관광 콘텐츠 근거 있음 |

| `강문해변화장실` | `VE / VE01 / VE010100` | 없음 | `건물` 분류에 들어온 편의시설 |
| `기린사우나` | `EX / EX05 / EX050100` | 없음 | 관광 온천과 같은 `온천/사우나/스파` 분류에 들어온 일반 사우나 |

2026-09-23 외부 통합 로그의 서울 응답에서는 `구로기계공구단지`가 `VE / VE05 / VE050100`으로 후보 풀에 진입했다. 한국관광공사 자체 설명도 이 장소를 관광·휴양 시설이 아니라 기계공구와 산업용품 유통 상가 단지로 소개한다. 이는 `VE050100`을 허용하면 PlanB가 요구하는 취향 비의존 기본 관광 후보에 산업 상업시설이 포함될 수 있음을 재현한 것이다. 공식 데이터 오류라고 단정할 근거는 없으며, PlanB의 더 좁은 제품 계약과 공식 콘텐츠 분류의 범위가 다른 사례다. ([한국관광공사 관광데이터: 구로기계공구단지](https://data.visitkorea.or.kr/linkedview/2591803))

이 표는 세 가지를 증명한다.

1. `contentTypeId=12`만으로 후보 품질을 보장할 수 없다.
2. 같은 코드에 서로 다른 성격의 장소가 섞일 수 있으므로, 코드 전체 제외에는 명시적인 제품 정책이 필요하다.
3. `센터`, `터미널`, `화장실`, `사우나` 같은 제목 금칙어를 계속 추가하는 방식은 새 혼합 분류가 나타날 때마다 다시 실패한다.

이미지 존재만 전역 필수조건으로 만드는 것도 안전하지 않다. 같은 응답의 `산계리3층석탑`, `굴산사지당간지주`처럼 역사 가치가 분명하지만 이미지가 없는 항목도 있다. 공식 명세의 `arrange=O/Q/R`을 사용하면 대표 이미지가 있는 결과만 받을 수 있지만, 이를 기본 조회로 바꾸면 이런 유효 후보가 사라진다.

## 현재 코드와 가장 작은 seam

현재 `Kor2ServiceHandler.searchAttractions`는 광역시는 시·도, 도 지역은 시·군 범위로 `/areaBasedList2`를 호출하며 `contentTypeId=12`를 사용한다 (`Kor2ServiceHandler.java:77-114`, `Kor2ServiceHandler.java:282-334`). 이 지역 계약은 문제 원인이 아니므로 유지한다.

`Kor2KeywordSearchResponse.Item`은 이미 `lclsSystm1`, `lclsSystm2`, `lclsSystm3`, `firstimage`, `firstimage2`를 모두 보존한다 (`Kor2KeywordSearchResponse.java:38-59`). DTO 변경도 필요 없다.

공통 필터 seam은 `TourismTool.selectAttractionCandidates`다 (`TourismTool.java:132-173`). 이 module은 현재도 다음 책임을 함께 가진다.

1. 관광특구·지구·권역 제목 제외
2. 후보 무작위화
3. 최대 40개 제한

품질 필터를 이 메서드의 무작위화와 제한 전에 적용하면 AI와 Java 보정기가 같은 후보 집합을 사용한다. `PlanTourismTool`이나 `MissingSlotCompleter`에 별도 필터를 추가하면 호출 경로별 계약이 갈라진다.

`AttractionTagPolicy`는 현재 `HS`, `NA`, `EX` 대분류와 허용된 `VE` 중분류를 태그로 바꾼다. 후보 허용 정책과 태그 정책은 서로 다른 책임이지만, `VE050100` 제거 후 `VE05`에는 허용된 소분류가 남지 않는다. `VE05 -> EXPERIENCE_ACTIVITY` 매핑을 그대로 두면 도달할 수 없는 정책이 남고 후보 허용 목록과 태그 정책이 다시 어긋난다.

허용 태그 계약 안에서는 `VE01`·`VE07`을 `HISTORY_CULTURE`, `VE02`를 `EXPERIENCE_ACTIVITY`, 기존 `VE03`·`VE04`를 `NATURAL_SCENERY`로 대응한다. `VE05` 매핑은 제거하고 빈 태그를 반환하는 기존 기본 동작에 맡기는 것이 가장 작은 일관된 변경이다. 이 정책은 `TourismTool`의 세분류 allowlist를 통과한 후보에만 적용한다.

필터는 원본 `Item`을 그대로 통과시키므로 `contentid`, 주소, 좌표, 이미지가 유지된다. 이후 `PlaceCandidateContext.record`가 `candidateId`, `lclsSystm2`, 주소, 좌표, 이미지를 기록한다 (`PlaceCandidateContext.java:31-48`).

## 권장 구현 계약

후보 선택 module의 public interface는 바꾸지 않고, 내부 predicate를 denylist에서 allowlist로 바꾼다.

```text
acceptable(item) =
    not zone title
    and lclsSystm3 != VE120300
    and (
        lclsSystm2 in ALLOWED_LEVEL_2_CODES
        or lclsSystm3 in ALLOWED_LEVEL_3_CODES
    )
```

권장 상수 집합은 다음과 같다.

```text
ALLOWED_LEVEL_2_CODES = {
    HS01, HS02, HS04,
    NA01, NA03, NA04,
    EX01, EX02, EX03, EX04, EX06,
    VE02, VE04
}

ALLOWED_LEVEL_3_CODES = {
    NA020100, NA020200, NA020300, NA020400,
    NA020500, NA020600, NA020800, NA020900,
    VE010200, VE010300, VE010400, VE010500,
    VE010600, VE010700, VE010800,
    VE030500,
    VE070100, VE070200, VE070300, VE070500, VE070600
}
```

`VE120300`은 위 집합에 원래 포함되지 않지만, 이미 확정한 제품 결정을 코드와 테스트에서 명시적으로 드러내기 위해 별도 제외 상수를 유지해도 된다. 반대로 `HS030200`, `EX050100`, `EX070100`, `VE010100`은 제목이나 이미지가 좋아 보여도 strict allowlist에서는 통과시키지 않는다.

2026-09-22 강릉 로그에서 반환된 관광 후보 40개에 이 계약을 적용하면 27개가 남는다. 해당 실행의 일정 생성에는 충분한 규모지만, 한 지역의 한 표본일 뿐 전국·비수도권의 충족성을 증명하지는 않는다. 필터 결과가 부족할 때 혼합 분류나 원본 후보를 복원하면 계약이 깨지므로, 기존 명시적 실패 경로를 유지하고 부족 지역을 별도로 계측하는 편이 안전하다.

필터 결과가 0개여도 원본 후보로 되돌리지 않는다. 현재 `TravelRecommendHandler`는 남은 후보 수만큼만 관광 슬롯 누락을 correction에서 면제하고 (`TravelRecommendHandler.java:263-323`), `MissingSlotCompleter`는 실제 기록된 후보만 사용한다 (`MissingSlotCompleter.java:370-399`). 끝까지 부족하면 `PlanService.validateTouristPlaceCounts`가 기존 `PLAN.EXCEPTION.INVALID_AI_PLACE` 경로로 거부한다 (`PlanService.java:1086-1127`). 새 fallback이나 예외 형식은 필요 없다.

## 테스트 seam

회귀 테스트는 `TourismTool.searchAttractionsByRegion` public interface에 둔다. `Kor2ServiceHandler.searchAttractions` 응답을 고정하면 외부 호출 없이 실제 후보 선택 seam을 검증할 수 있다.

최소 테스트는 다음과 같다.

1. `HS01`, `NA01`, `EX03`, `VE04` 같은 허용 중분류는 유지된다.
2. `NA020900`, `VE010600`, `VE030500`, `VE070100` 같은 허용 소분류는 유지된다.
3. `HS030200`, `EX050100`, `EX070100`, `VE010100`은 제목·이미지와 관계없이 제외된다.
4. `VE120300`은 제목·이미지와 관계없이 제외된다.
5. `VE050100`은 제목·이미지와 관계없이 제외되며, 실제 회귀 fixture로 `구로기계공구단지`를 사용한다.
6. 분류 코드가 없거나 새 코드면 제외된다.
7. 전부 제외된 경우 원본 후보를 복원하지 않는다.

테스트는 `TourismTool.searchAttractionsByRegion`에서 결과 후보만 검증한다. private predicate나 상수의 구성 자체를 테스트하지 않는다.

## 제외한 대안

- **`contentTypeId=12` 신뢰**: 실제 재현에서 이미 실패했다.
- **혼합 분류를 모두 유지**: 합법적인 종교·문화유산과 유람선은 보존하지만 일반 교회·사우나·여객터미널도 계속 들어온다. strict allowlist 목표와 맞지 않는다.
- **제목에 `교회`, `센터`, `터미널`이 있으면 전역 제외**: 분류 근거가 없어 오탐 범위가 넓다.
- **대표 이미지 없는 후보 전체 제외 또는 `arrange=O` 사용**: 이미지 없는 역사 유적도 제거한다.
- **denylist를 계속 확장**: 현재 알려진 사례는 막지만 알 수 없는 코드와 새 혼합 분류를 기본 허용한다.
- **`lclsSystmCode2`를 요청마다 호출**: `areaBasedList2` item에 코드가 이미 있다. 네트워크 호출과 cache만 늘어난다.
- **AI 프롬프트로만 회피**: Java 보정기도 같은 후보에서 자동 선택하므로 공통 후보 seam에서 제거해야 한다.
- **새 interface나 adapter 추가**: 현재 `TourismTool`이 후보 선택 책임을 이미 소유한다. private predicate면 충분하다.
