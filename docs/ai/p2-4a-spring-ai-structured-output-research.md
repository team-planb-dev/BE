# P2-4A: Spring AI 2.0.0 구조화 출력과 Tool Calling 조사

조사일: 2026-10-08. 기준 버전은 저장소의 `springAiVersion = "2.0.0"`이며, 버전 차이를 피하려고 Spring AI 동작은 가능한 한 `v2.0.0` 태그의 소스로 확인했다. [저장소 빌드 설정](../../build.gradle#L20), [Spring AI 2.0.0 소스](https://github.com/spring-projects/spring-ai/tree/v2.0.0)

## 현재 호출 방식과 구조화 출력의 범위

- `BeanOutputConverter<T>`는 Java 타입에서 JSON Schema를 **생성**하고, 별도 `JsonMapper`로 모델 텍스트를 **역직렬화**한다. 생성 스키마와 사용자 정의 역직렬화 규칙이 동일한 의미를 보장하는 것은 아니다. 현재 저장소도 응답 DTO용 사용자 정의 `JsonMapper`를 주입한다. [BeanOutputConverter 소스](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/converter/BeanOutputConverter.java#L126-L179), [현재 설정](../../src/main/java/com/planb/global/config/ai/AiOutputConverterConfig.java#L22-L56)
- 현재 `OpenAiClient`는 `outputConverter.getJsonSchema()`를 보정한 뒤 `OpenAiChatOptions.responseFormat(JSON_SCHEMA)`로 보내고, `.content()`를 받아 `outputConverter.convert()`를 직접 호출한다. `getFormat()`을 프롬프트에 붙이는 `ChatClient.entity(...)` 경로가 아니다. Spring AI 2.0.0 `OpenAiChatModel`은 이 옵션을 OpenAI `response_format.json_schema`로 변환하면서 `strict(true)`를 지정한다. [현재 클라이언트](../../src/main/java/com/planb/ai/client/OpenAiClient.java#L147-L175), [OpenAiChatModel 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/models/spring-ai-openai/src/main/java/org/springframework/ai/openai/OpenAiChatModel.java#L685-L709), [BeanOutputConverter 소스](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/converter/BeanOutputConverter.java#L191-L215)
- `ChatClient.entity(converter, spec -> spec.useProviderStructuredOutput().validateSchema())`라는 2.0.0 API도 있다. 여기서 `validateSchema()`는 최종 모델 텍스트를 JSON Schema로 검사하고 오류를 담아 재호출한다. DTO 변환은 그 뒤에 실행된다. 현 호출 경로는 이 API를 사용하지 않고 파싱 또는 도메인 검사 실패 시 전체 호출을 한 번 더 실행한다. 두 재시도 방식을 함께 도입하면 호출 횟수와 tool 실행 횟수가 달라진다. [ChatClient API](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/ChatClient.java#L186-L273), [DefaultChatClient 변환 순서](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/DefaultChatClient.java#L525-L565), [현재 재시도](../../src/main/java/com/planb/ai/client/OpenAiClient.java#L96-L144)
- `EntityParamSpec`는 native 구조화 출력과 JSON Schema 검증 옵션만 제공한다. `validateSchema()`는 JSON 텍스트를 검증하며, 변환된 DTO에 대한 임의의 `Predicate<T>`를 전달하는 콜백은 없다. 같은 모델 호출의 DTO 변환 전에 도메인 검사까지 하려면 직접 advisor/변환기를 작성해야 한다. 현재의 변환 후 `Predicate<T>` 검사가 가장 작은 명시적 경계다. [EntityParamSpec API](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/ChatClient.java#L186-L220), [검증 advisor 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/advisor/StructuredOutputValidationAdvisor.java#L107-L193), [현재 검사](../../src/main/java/com/planb/ai/client/OpenAiClient.java#L118-L143)

## Strict 스키마와 프롬프트 제약

- OpenAI strict Structured Outputs는 JSON Schema **부분집합**만 허용한다. 루트는 객체여야 하고, 객체의 모든 속성은 `required`에 있어야 하며, 객체마다 `additionalProperties: false`가 필요하다. 선택적 의미는 속성을 생략하는 대신 `required`를 유지하면서 `type: [기존 타입, "null"]`로 표현한다. 지원하지 않는 스키마를 `strict: true`로 보내면 API 오류가 난다. [OpenAI 공식 지원 스키마](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)
- Spring AI 2.0.0 스키마 생성기는 기본적으로 속성을 `required`로 만들고, 일반 객체에는 `additionalProperties: false`를 재귀적으로 붙인다. 단, `@ToolParam(required = false)`, `@JsonProperty(required = false)`, `@Nullable` 등은 필수 여부를 바꿀 수 있으므로 DTO의 실제 `getJsonSchema()`를 검사해야 한다. `@Nullable`만 붙인 Java record가 OpenAI strict에서 요구하는 **필수 키 + null 허용 타입**을 자동으로 만족한다고 가정해서는 안 된다. [JsonSchemaGenerator 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/util/json/schema/JsonSchemaGenerator.java#L48-L111), [SpringAiSchemaModule 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/util/json/schema/AbstractSpringAiSchemaModule.java), [OpenAI 필수 및 null 규칙](https://developers.openai.com/api/docs/guides/structured-outputs#all-fields-must-be-required)
- 현재 `normalizeSchema()`는 일부 일정 필드의 `required`를 유지하면서 타입에 `null`을 추가하고, `date`/`time` 형식 키워드를 제거한다. 이는 저장소의 strict 스키마 보정 규칙이다. 스키마를 바꾸면 중첩 객체까지 포함한 실제 출력 스키마와 역직렬화 결과를 함께 확인해야 한다. [현재 스키마 보정](../../src/main/java/com/planb/ai/client/OpenAiClient.java#L177-L241), [Spring AI 스키마 생성기](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/util/json/schema/JsonSchemaGenerator.java#L173-L190), [OpenAI 지원 스키마](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)
- OpenAI 문서는 스키마의 키 이름을 명확히 하고 중요한 키에 설명을 붙일 것을 권한다. 이 설명과 프롬프트는 모델이 **값을 선택하는 기준**을 전달하는 수단이며, strict 스키마는 그 값이 실제 후보인지, 일정 날짜 수가 맞는지, 장소가 중복되지 않는지 같은 도메인 사실을 증명하지 않는다. 거절 또는 출력 중단 시에도 스키마 밖 응답이 가능하다. [OpenAI 스키마 팁과 입력 처리](https://developers.openai.com/api/docs/guides/structured-outputs#tips-for-your-json-schema), [OpenAI 제한 사항](https://openai.com/index/introducing-structured-outputs-in-the-api/#limitations-and-restrictions)
- 따라서 P2-4A에서는 도메인 규칙을 프롬프트에 명확히 적되, 실제 후보 ID·개수·중복·상호 일관성은 Java 검증으로 확정하는 것이 적절하다. 이는 strict 스키마가 JSON 모양을 제한하지만 값의 의미까지 보장하지 않는다는 공식 제한에서 도출한 설계 판단이다. [OpenAI 제한 사항](https://openai.com/index/introducing-structured-outputs-in-the-api/#limitations-and-restrictions), [현재 후처리 검사](../../src/main/java/com/planb/ai/handler/TravelRecommendHandler.java#L162-L189)

## Tool 등록과 호출

- Spring AI 2.0.0 `.tools(Object...)`는 `@Tool` 메서드가 있는 객체, `ToolCallback`, `ToolCallbackProvider`와 이들의 배열·컬렉션을 받는다. 객체는 `@Tool` 메서드별 callback으로 변환된다. `@Tool(name=...)`을 지정하지 않으면 Java 메서드명이 도구 이름이다. [ChatClient 2.0.0 API](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/ChatClient.java#L376-L418), [DefaultChatClient 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/DefaultChatClient.java#L944-L985), [Tool annotation](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/tool/annotation/Tool.java#L34-L50)
- 한 요청의 도구 이름은 유일해야 한다. 2.0.0은 callback 이름 중복을 발견하면 `IllegalStateException`을 던지고, 하나의 `@Tool` 객체 묶음 안의 중복은 provider 생성 시 `IllegalArgumentException`을 던진다. 새 도구 추가 전 현재 `PlanTourismTool` 및 연결된 callback/provider의 이름을 함께 확인해야 한다. [ToolCallingChatOptions 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/model/tool/ToolCallingChatOptions.java#L84-L93), [MethodToolCallbackProvider 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-model/src/main/java/org/springframework/ai/tool/method/MethodToolCallbackProvider.java#L119-L125), [현재 도구](../../src/main/java/com/planb/ai/mcp/PlanTourismTool.java#L18-L86)
- `ChatClient`의 `ToolCallingAdvisor`는 모델이 제안한 도구 호출을 애플리케이션에서 실행하고 결과를 대화에 넣어 모델을 다시 호출한다. 최종 응답에 도구 호출이 없어야 호출자에게 반환한다. 따라서 도구 검색의 결과가 최종 DTO에 실제 사용됐는지 여부는 별도 검증 대상이다. [Spring AI Tool Calling](https://docs.spring.io/spring-ai/reference/api/tools.html#_the_tool_calling_loop), [ToolCallingAdvisor 2.0.0](https://github.com/spring-projects/spring-ai/blob/v2.0.0/spring-ai-client-chat/src/main/java/org/springframework/ai/chat/client/advisor/ToolCallingAdvisor.java)
